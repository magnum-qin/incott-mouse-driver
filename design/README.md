# design/ — 界面设计与校对工具

这个目录**不参与打包**。里面是两类东西：长期有用的工具（`preview/`），和选型过程的留档（`archive/`）。

## 界面是怎么定的

界面在 2026-11-23 整体重做过一次，分两步，每一步都是做出真实渲染的样张再选：

1. **视觉风格** —— 四个候选方向并排比较，选定了「D 的形态 + B 的配色」：
   - D（Instrument）的形态：编号菜单与章节、指示灯、等宽数字、推子和刻度尺、带灯的实体按键、内凹的点阵读数屏。
   - B（Graphite）的配色：中性无色偏的深灰，白色是唯一信号色，画面里只有电池灯和档位灯带颜色。
2. **布局** —— 在选定的风格里做了三个可点击的样稿，选定了「方案一 · 左侧编号菜单」：
   左侧编号菜单，中间内容，右侧常驻读数屏，底栏放配置键和应用。

设计系统本身就在 `ui/style.css` 的开头（令牌 + 几条原则），那是唯一的权威来源。
要做视觉决策，先看完这里再动手。

### 几条硬规矩

- **层级不靠色相。** 单色界面靠三样东西分层：明度（底 → 卡片 → 按键 三级）、字重与字体
  （中文用界面字体，数字和编号用等宽）、亮着的灯。
- **发光只给指示灯**（6px 的光晕）。不给文字、边框、卡片加光晕，不用渐变。
- **白色只表示"亮着"**：当前项、选中的按键、主按钮、LED。不要拿白色做普通强调。
- **颜色只留给有含义的东西**：电量（绿 / 黄 / 红）、档位灯（六色）、连接状态（绿）。
- **等宽字体栈尾必须带 `"Microsoft YaHei UI"`**，否则等宽字体里的中文会回退成宋体。
- **说明文字能不要就不要。** 界面上只留操作必需的文字，解释性的内容放悬停提示（`title`）。
- **装饰不能长得像字符。** 刻度线一类的细小标记要稀疏、有长短层级。推子的刻度曾经是每 2% 一道
  1px 短线，挨着数值框看就是一串「1」（界面缩放 1.3 倍 + 系统 150% 时尤其明显）。
  这类东西要在真实的缩放条件下看（预览地址加 `scale=1.3`，截图加 `--scale 1.5`）。

## 动效

这套界面的隐喻是一台硬件：按键带指示灯、推子、读数屏、编号菜单。动效沿用同一套物理逻辑。
令牌在 `ui/style.css` 的 `--t-press / --t-fast / --t-exit / --t-base / --t-settle` 和三个 `--ease-*`，
时序逻辑在 `ui/app.js` 开头的「动效小工具」。

### 原则

**三类东西，三种动法**

| 类别 | 例子 | 动法 |
|---|---|---|
| 按键 | 所有键、菜单项 | 按下有行程（整个键帽下沉 1px，立刻到位），松开后**外壳**闪一下。里面的文字和图标是印在键帽上的：不缩放、不变亮。选中靠灯的转移表达，不靠位移 |
| 灯 / 状态 | 亮灭、开关、启用 / 禁用、指示灯 | 亮起快、熄灭略缓，都是 120ms；不弹跳 |
| 读数 | 读数屏、数值框、状态文字 | 数字**即时变化**，像显示屏；至多短促亮一下表示「变了」。绝不让数字滚动 |

**换页 = 换屏**：旧页先退出（110ms，淡出并向左 6px），退完新页再进入（180ms，从右侧 8px 滑入）。
先出后进、不重叠——两页都是密集内容，叠在一起看不清。方向固定从左到右（菜单在左、内容在右）。
中途再点别处也要接得上：退出途中改目标，退出照原节奏走完、进的是最新的目标；退出途中点回原来那一页，
原路返回；进入途中再点别处，从显示到一半的样子开始退，不先跳成完整的一页。

**列表先消失再补位**：删掉的行留一个残影淡出（120ms），其余行同时滑上来补空（220ms）；新增的行淡入。
残影画在行的**下面**，补位的行上来时把它盖掉（画在上面会叠出重影）。列表的高度跟着一起过渡，
列表下方的内容（按钮、卡片底边）才不会先跳到位；新增的行是从列表里「展开」出来的。

**其余几条**

- 进出成对：有进场就有退场（页面、菜单、列表行、状态提示）。例外只有两个：焦点环
  （无障碍要求即时出现）和交给系统处理的窗口显隐。「它是在说没事了」不是例外的理由——
  未应用提示消失时一样先淡出，110ms 不会抢注意力，瞬间消失才会显得生硬。
- 一套时长、一套缓动：进场减速（`--ease-out`），退场加速（`--ease-in`），不混用。
- 幅度小：位移不超过 8px，而且一定带透明度；不做缩放文字、模糊、回弹。
- 不打断输入：连续点击时重新定向而不是排队等动画播完。
- 后台变化只用轻提示：设备推送（电量、换档）只让变化的值亮一下，不位移、不抢注意力。
- 跟随系统的「减少动画」设置（`prefers-reduced-motion`）：CSS 侧把时长压到 0，JS 侧跳过等待。

### 实现上的四条约束

- **按键组要原地更新，不要重建元素。** 灯的亮灭、启用 / 禁用靠 CSS 过渡表达，元素一重建过渡就没了，
  点击回执也会被抹掉。统一走 `syncKeys()`。
- **常驻 + 过渡，而不是出现 / 消失。** 指示灯、当前档的白条这类东西平时就在原位（透明度为 0），
  靠透明度和缩放过渡显隐，这样灭和亮都有过程。
- **要打断的动画走 Web Animations API，每段都从「当前看到的样子」出发。** 用「CSS 类 + 定时器」
  排时序的话，中途再点一下就接不上（等待被重新计时、两段动画互相盖掉）。换页、补位、显隐
  （`toggleShown()`）都是这么做的。时长和缓动只在 `style.css` 的令牌里定义一次，
  这几处启动时从 CSS 变量读一份，不另写常数。
- **点击回执画在背景上，不碰内容。** 键面的那一闪是背景图最上层的一个半透明层，透明度走注册过的
  自定义属性 `--flash`（`@property`）。所以 `.key` / `.cta` / `.x` 的底色一律写 `background-color:`——
  写成 `background:` 简写会把这一层抹掉，那个状态下点了就没反应。

### 检查动效

动画的问题只有看运动的帧才看得出来（闪一下、跳一下、卡一帧）。改了动效之后把全部场景重录一遍：

```bash
node design/preview/motion.mjs --all          # 每个场景一组帧 + 连拍图，在 design/shots/motion/<场景>/
node design/preview/motion.mjs page --crop 0,60,300,130 --every 1   # 单录一个，放大某块区域逐帧看
node design/preview/motion.mjs --list         # 看有哪些场景（30 个；标了「仅预览」的有副作用，不能在真实应用里跑）
```

默认用 GPU 合成录，和应用的 WebView2 是同一条渲染路径。连拍图只取了部分帧、想自己挑着看时直接调拼图脚本：

```powershell
powershell -NoProfile -File design/preview/strip.ps1 -Dir design/shots/motion/stage-remove `
  -From 1 -Every 1 -Max 9 -Cols 3 -Width 600 -Crop "180,128,660,420"   # 裁剪坐标按 1080×720 的应用窗口算
```

预览页终究不是应用本身。拿不准某一帧是真的还是录帧的假象时，录真实应用：

```powershell
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS='--remote-debugging-port=9333'
.\src-tauri\target\release\incott-mouse-driver.exe
```

```bash
node design/preview/motion.mjs page --attach 9333 --full --out design/shots/motion/live/page   # 每个场景各录一次
```

`--attach` 只跑既不写鼠标、也不写本地配置的场景（换页、按键组、增删档位、增删宏动作、菜单、窗口键的悬停）。
有副作用的场景在 `SCENARIOS` 里标了 `previewOnly: true`，录制器遇到会直接拒绝、列出原因，不用靠记：

- **会写鼠标的**：`apply-done`。
- **会写本地配置的**：`profile`。切换配置键会把「正在编辑的内容」存进用户的本地预设
  （localStorage 的 `incott-config`），这是持久的数据，重启也不会恢复。「不写鼠标」不等于「没有副作用」。
- **会碰设备的**：连接 / 断开、推送、点窗口控制键（会真的最小化 / 最大化）。

以后给场景加步骤时，只要它点了会保存或会写设备的控件，就打上这个标记。

录完界面会留着没应用的改动，重启应用即可。

和预览里不同、要留意的几点：

- **真实应用里状态是跨场景延续的**（预览每次都重新加载）。录制器会在每个场景开始前先切到它所在的页面，
  但「当前档」「已选中的回报率」这类值不会被重置——连着录两次同一个场景，第二次可能什么都没变。
- 每个场景要各自指定输出目录（`--out design/shots/motion/live/<场景>`），否则后一个会覆盖前一个的帧。
- **预览默认是 1 倍缩放、系统缩放 100%，真实应用不一定是。** 这台机器上 1080×720 的窗口自动算出来是
  1.3 倍界面缩放、已经进了紧凑布局，系统缩放是 150%——预览里验证过的东西，要在真实配置下再看一遍
  （预览地址加 `scale=1.3` 可以复现布局，截图加 `--scale 1.5` 可以复现渲染）。

## 图标

应用图标的源文件在 `design/icon/IncottFramedMouse/`，用 [xzhih/app-icon-skill](https://github.com/xzhih/app-icon-skill)
的 `app-icon-gen` 技能做的：一份 JSON 规格（`tmp/work/spec.json`）描述几个语义图层，
脚本据此生成分层的 SVG、圆角预览图和无圆角源图，并跑一套结构检查。源文件必须保持扁平、分层：
实心填充，不用描边、渐变、光晕，「凹进去」的部分用底色的覆盖层表达，不留孔洞。

它和托盘图标是同一个构成：一个只描边的圆角方框，里面一只细长的鼠标、一枚绿灯。应用图标多一块底板——
它要放在浅色、深色各种背景上，不能像托盘图标那样让墨色跟着主题走。

| 图层 | 内容 |
|---|---|
| 底板 | 石墨灰 `#232327` 的圆角方块（圆角 22%）。Windows 没有系统级的圆角裁切，用的是带圆角的预览图 |
| 方框 | `#EDEDEE`（`--text`）的圆角方块，边长是画面的 74%；上面盖一块缩进 32 像素的底色方块，留下一圈空心方框 |
| 鼠标 | `#EDEDEE` 的实心轮廓：顶部椭圆拱、直边、底部收圆。宽 394、高 522，宽高比和托盘图标一样 |
| 分键线 | 底色的覆盖层：离顶边一点、通到 40% 高度的圆头短槽（通到顶的话会和上面的框连成一条线） |
| 指示灯 | `#46C98C`（`--success`，标题栏「已连接」的那盏绿灯）。画面里唯一的彩色 |

- **方框是来撑外轮廓的。** 上一版（`IncottLitMouse/`）是底板 + 一只占画面 43% 宽的鼠标，大图好看；
  但小尺寸得把鼠标加粗才不显小，24 像素下宽到 74%。托盘图标也走过同一条弯路，最后是用户提出加框才解决的
  （见下面「托盘图标」）。2026-11-26 用户看到安装包的图标，说「还是胖胖的鼠标图标」——应用图标和托盘图标是两套东西，
  当时只改了托盘。现在两边统一：外轮廓由框负责，鼠标在哪个尺寸都保持细长。
- 同一批还做了几个方向留档：`IncottLitMouse/`（底板 + 实心鼠标，上一版）、`IncottKeycap/`（白键帽、石墨色鼠标）
  和 `IncottLineMouse/`（线稿，32px 以下认不出来）。对比图见 `design/icon/compare.png`
  （从上到下：上游的旧图标、上一版、键帽、线稿、现在）。
- 上游的旧图标（紫色渐变底 + 深紫色鼠标）留在 `design/archive/icon-upstream/`。

### 小尺寸帧

`icon.ico` 里 16 / 24 / 32 / 48 / 64 五帧不是缩出来的，是 `design/icon/small-frames.mjs` 按大图的比例现画的；
256 那一帧是大图缩出来的（`npx tauri icon`）。

- **比例只有一个。** 脚本里的 `MASTER` 记的就是大图里的像素数，各尺寸照着缩，鼠标不再随尺寸变胖。
- **线宽不等比。** 16 像素下线要 1 像素才看得见，图越大在比例上越细（`strokeFor`）；方框外沿的位置取整到像素边界，
  直边才是实的。
- 24 像素及以下底板更黑、线条纯白：细线被抗锯齿冲淡以后还得站得住。

| 边长 | 方框线宽 | 底板 | 线条颜色 |
|---|---|---|---|
| 16 / 24 | 1 像素 | `#111113` | 纯白 |

### 托盘图标

托盘里是**一个只描边的圆角方框，里面一只单色鼠标**，直接画在任务栏上，中间不填色。
外轮廓和这一排里的方形图标一样大，分量却和那些直接画在任务栏上的单色图形相当。
应用图标是同一个构成加一块底板（见上面「图标」）。
鼠标是读数屏里那只线稿鼠标的简化版；**大小是量着旁边的图标定的**（见下面）。
用**鼠标的深浅和指示灯**表示状态：

| 样子 | 状态 |
|---|---|
| 框 + 半透明的灰鼠标，没有灯 | 未连接（灯灭） |
| 框 + 实心鼠标，绿灯 | 已连接，电量充足（或者电量还没读到） |
| 框 + 实心鼠标，黄灯 | 电量 25~60 |
| 框 + 实心鼠标，红灯 | 电量 ≤25 |

- **外轮廓交给框，是因为鼠标自己撑不起来。** 鼠标得高大于宽，再怎么加宽也只有旁边方形图标的七成宽：
  第三版宽 12 × 高 22 像素，用户说「太瘦」；第四版量着邻居加宽到 16 × 22，用户还是说「太瘦了，是不是加框会更好」。
  第五版照这个思路改：框占满整个图标位（150% 缩放下 24 × 24 像素），鼠标缩回 12 × 16 放进去，宽高比和第四版一样。
- **框只描边，不填色。** 第一、二版是「深色圆角底板 + 白色鼠标」，用户说「太胖了，不美观，换一个显示方式」：
  实心的底板逼着图标得填满才够分量，而旁边的图标都是直接画在任务栏上的。
  空心方框有了方形的轮廓，墨量只比第四版多一点（见下面的数字）。
  当时还比过「纯线条鼠标」（太轻，又会显小）和「电量环」（像正在加载的转圈，也看不出是哪个应用）。
- **数字是量出来的，不是估出来的。** 从真实的托盘截图里量旁边的图标：都是 24×24 像素。
  墨量按「每个像素相对任务栏底色的暗度加起来」算（彩色图标按这个算法偏低，不拿来比）：
  ChatGPT 的线球 197、Notion 258、Z 的实心方块 405。我们的几版：第三版 195、第四版 253、第五版 278——
  和 Notion 差不多，比 ChatGPT 重、比实心方块轻得多。框线加粗到 2.5 像素是 310，开始压过邻居；
  框缩到 22、鼠标缩到 10 × 14 的话，框里显得空、鼠标显小。
- **框：圆角量的是旁边那个方形图标**（150% 缩放下 5.4 像素，逐行对得上）；线宽按 4/3 个逻辑像素取整到整像素
  （100% 缩放下 1 像素、150% 下 2 像素），里外两个沿都落在像素边界上，线才是实的。
- **内部结构只留分键槽**，离顶边一点、通到 40% 的高度（通到顶的话会和上面的框连成一条线）。
  试过给宽一点的鼠身加「按键分界线」来切开大面积：两道斜向上的短线看起来像朝下的箭头，
  横贯机身的横线把顶上切成两只「耳朵」（像一张脸）。都淘汰了。
- **没连接时鼠标变灰，不画空心。** 第四版没连接是空心轮廓。放进框里以后，12 × 16 的鼠标挖空、再加上分键线和灯座，
  远看是个感叹号。改成鼠标只画一半不透明度（叠在任务栏上是灰的）、没有灯：形状不变，一眼看得出是关着的，外轮廓也不变。
- **墨色跟随系统主题**：浅色任务栏用深墨，灯色压暗一档才看得清；深色任务栏用浅墨，灯色就是界面里的三种。
  读的是注册表里的「Windows 模式」（任务栏和开始菜单跟着它走，和「应用模式」可以不一样），
  系统切换主题时会重画（`main.rs` 里的 `ThemeChanged`）。
- 在 `src-tauri/src/tray.rs` 里按托盘的实际尺寸现画（`tray_glyph()`），比例以「16 逻辑像素的图标位」为单位。
  边缘的抗锯齿靠有向距离函数。
- 尺寸按任务栏所在主屏的缩放算：托盘的一个图标位是 16 个逻辑像素（100% 缩放是 16，150% 是 24）。
  尺寸不对系统就会把它缩放，边缘发虚。

设计规则由 Rust 单元测试钉着（`cd src-tauri && cargo test --release`，6 项）：连上时框和鼠身不透明、灯是灯色、
框和鼠标之间透明、分键线透明；断开时框不变、鼠身一半不透明、没有灯；墨色跟着主题；16~32 像素都画得出来、框占满图标位；
外框是 24×24，墨量（这里是不透明度加起来）和第四版相近，没连接时轻一截。以后改画法先改测试里的预期，别让它们悄悄失效。

要改样子：改 `tray.rs` 里的 `tray_glyph()`，然后**把候选画进一张真实的托盘截图里比**——
截一段托盘，量出自己那个图标的位置，用同样的像素把候选画上去，再放大了和旁边的图标一起看，
宽窄和墨量拿邻居的数字对照。只看单独的小图会判断错：前几版都是这么定下来的。
连着和没连接两种状态要分别看，并且放在邻居中间看——没连接的画法就是在这样的放大图里才看出像个感叹号的。
任务栏被全屏窗口盖住时屏幕上截不到：用 `PrintWindow` 让任务栏窗口自己画出来（`Shell_TrayWnd`，标志 `PW_RENDERFULLCONTENT`），
盖着也能拿到真实的托盘像素；实在没有，再从以前留下的 4 倍最近邻放大图里把原始像素无损还原出来
（每个 4×4 的方块颜色必须完全一致）。

踩过的坑：

- **换了 `.ico`，exe 里还是旧图标。** Tauri 的构建脚本把图标编进 Windows 资源，却没有把这个文件登记为
  构建脚本的输入，所以资源不会重新编译。`src-tauri/build.rs` 里自己登记了一行 `rerun-if-changed`。
- **安装包显示的是 NSIS 的默认图标。** 这个版本的 Tauri 不会自动把应用图标用在安装包上
  （生成的脚本里 `INSTALLERICON` 是空的）。`tauri.conf.json` 的 `bundle.windows.nsis.installerIcon`
  和 `uninstallerIcon` 要明确写。
- **同一路径的 exe 换过图标后，系统可能还返回缓存的旧图。** 先复制成一个新文件名再取；
  资源管理器里不刷新就跑一次 `ie4uinit.exe -show`。
- **技能的脚本在 Windows 上拒绝任何输出目录**（它按 `/` 切分路径来数目录深度，而 Windows 的规范路径是反斜杠）。
  已经给装在本机的副本打了一行补丁；以后更新技能，这个补丁要重打。
- **`GetSystemMetrics(SM_CXSMICON)` 不等于托盘图标的尺寸。** 它跟着系统字体走，这台机器 150% 缩放时报的是 33，
  而托盘的槽位是 16 逻辑像素 × 1.5 = 24。第一版按 33 画，系统再缩到 24：边缘发糊，鼠标比例还是 32 像素那一档的
  （更细）。「屏幕上量到 24×24」说明不了画对了——系统总会把它缩到槽位大小；要把任务栏截图和代码的输出
  **逐像素**比对（把候选尺寸都画一遍，在截图里找哪一张能完全对上）。
- **`npx tauri icon` 会把小尺寸帧冲掉**：它用大图重写全部帧，16 / 24 / 32 / 48 / 64 都变回大图直接缩下来的样子。
  跑完要再跑一遍 `small-frames.mjs`；忘了的话 `npm test` 会报出来。
- **图标的大小「差不多」要先量，凭感觉调会来回 overshoot。** 第一版托盘图标和旁边的底板一样大，差的是反差和占比；
  照这个结论把鼠标加粗之后，用户说太胖（两次都是只调参数、没换做法——真正的毛病是那块底板，见「托盘图标」）。
  换成不带底板之后，我按鼠标本来的窄长比例画，用户又说太瘦、要「加宽到和其他图标差不多的大小」。
  前三次都是没有数字。第四版先量：邻居大多 24×24 像素，那一版宽 12 像素——确实只有一半，数据早就指出来了。
  **用户说「和某某差不多」时，先把参照物的尺寸和分量量出来，再定自己的，并且用测试钉住。**
  判断图标在托盘 / 任务栏里的分量，要把它和**真实的相邻图标**放在同一排里比：截一段真实的任务栏，
  量出自己那个图标的位置，把候选按同样的像素画上去，最后整体放大了看。只看大图，或者只看单独的小图，都会判断错。
  第四版量着邻居加宽到 16 × 22，用户还是说太瘦，并且自己提出了办法：加框。**参照物是方形的时候，
  细长的形状加宽也追不上，得换一个撑起外轮廓的办法**（第五版的框），别在原来的形状里继续调参数。
- **描边公式的次序不能反。** 描边 = 落在轮廓**外**沿之内的覆盖率 − 落在**内**沿之内的覆盖率。写反了算出来是负的：
  在 Rust 里被截成 0，轮廓整个消失；在预览用的 JS 里被 Buffer 悄悄回绕成一个很小的正数，看起来只是一条偏细、发虚的线。
  两种情况都不报错，是给关键像素逐个推算、写单元测试时才发现的（那时已经照着预览定了方案）。
  覆盖率相减的结果要断言非负，或者用测试把关键像素钉住（现在框和描边都取了 `.max(0.0)`）。
- **别拿照公式手算的像素当验证，先把代码画的导出来看。** 第五版我把鼠标的高度写成了 `32.0 * u / 6.0`
  （8 像素，应该是 16）：照公式推算的测试值全对不上，是把 `tray.rs` 里的画图代码抽出来单独编译、
  把像素打成字符画才看清圆拱顶整个没了。测试里先写下预期的像素，跑不过就导出来看，别改预期去迁就。
- **预览时候选要叠在截图上，先确认截图里那一格是空的。** 截图里那个位置本来画着旧图标，直接叠上去，
  新旧两个图标混成一块实心的，看着像候选本身画错了。先把那一格清成任务栏底色。
- **两种「墨量」算法的数字不一样，写下来时说清用的是哪种。** 一种是图标的不透明度加起来（在代码输出上量），
  一种是相对底色的暗度加起来（在截图上量，邻居也只能这么量）。第四版按前者是 293、按后者是 253。
  之前的说明混用过：说自己用前者，说邻居用后者。
- **非整数的线宽发虚。** 框线取 2.5 像素时里外两个沿都不在像素边界上，放大了看是糊的；按缩放取整到整像素。
- **托盘里自己的图标位置每次启动都可能变。** 用 UI Automation 找（任务栏窗口下 AutomationId 为 `NotifyItemIcon`、
  Name 含应用名的按钮），别写死坐标；截图用显示器像素（先 `SetProcessDPIAware`）。
  任务栏被别的窗口盖住时 `CopyFromScreen` 截到的是盖在上面的窗口，改用 `PrintWindow`（见上面「托盘图标」）。
- **小尺寸认不认得出来，只能看真实的任务栏尺寸。** 用 `icon-sheet.ps1` 或 `small-frames.mjs --sheet`
  先筛一遍，定稿前再放到真实任务栏上看。

只发读命令，并 `read_timeout` 听一会儿鼠标的主动上报。
插线充电时的实测数据（`docs/protocol.md` §4）就是这么量的。

要验证「连着接收器时鼠标插上线」的自动切换，又不想真的拔插：通过调试端口在页面里
`window.api.listDevices()` 拿到接收器的路径，`window.api.openDevice(路径)` 把它按到接收器上，
再 `window.__TAURI__.event.emit('hid://devices')`——Rust 的设备监视在有增减时发的就是它。
注意直接调 `openDevice` 绕过了界面的连接流程，标题栏的文字不会跟着变；
判断以 `window.api.getState()` 和 `tray_get_status` 为准，切换完成后标题栏才更新。
做完比对一遍 `localStorage.getItem('incott-config')`，确认没动用户的配置。

### 踩过的坑

- **无头浏览器的窗口宽度有下限**（约 500px）。直接把窗口设成 268 宽去截托盘浮层，
  得到的是从更宽的页面上裁下来的左上角，看起来像"内容被截断"，其实界面没问题。
  要看小尺寸界面，用 `zoom.html` 的 `pw=` / `ph=` + `z=` 放大看。
- **过渡动画可能停在起始帧。** 截图加 `still`。
- **多个预览并排时会互相抢焦点**：后打开菜单的那个会触发前一个的 `focusout`，把菜单收起。
  界面这个行为是对的（真机只有一个窗口）；预览指定了 `open=` 时会按住菜单。
- **容器查询里的 `em` 不跟随自定义的界面缩放**（按浏览器初始字号算）。需要同时看
  窗口宽度和缩放倍率的布局判断，用脚本量（见 `ui/app.js` 的 `syncCompactLayout`）。
- 模拟脚本在 `<head>` 里就执行了，那时 `<body>` 还没解析——不能靠查元素来判断是哪个页面。
- **带留白的「填充」不能拿百分比当背景图宽度。** 标题栏的电量图标原来是一张背景图，宽度写成电量的百分比：
  百分比是相对整个图标算的，再加上左边让开的 2px，电量一过 88% 填充就顶穿右壁（2026-11-26 用户截图问
  「电池图标好像穿过头了，是设计还是 bug」——是画法的 bug）。现在填充是绝对定位的 `::before`，
  宽度 `calc((100% - 4px) * var(--lvl))`，只在左右各留 2px 的内槽里走。
  推子那条轨道没有留白，用同样的百分比背景图是对的。
- **「图标」有两套。** 托盘图标是 `tray.rs` 现画的；应用图标是 `icon.ico`，用在 exe、安装包、开始菜单和任务栏按钮上。
  2026-11-26 改托盘时没动应用图标，它的小尺寸帧还是早先加粗的鼠标，用户看到安装包的图标问「为什么还是胖胖的鼠标图标」。
  用户说「图标」时先对一下是哪一套；两套该是同一个构成，改了一个要回头看另一个。
- **无线鼠标睡着时什么都读不到。** 实测（docs/protocol.md §4）：睡着后 `0x89` 回 0、整套配置读回来是空的、也没有上报，
  重连和读配置都叫不醒它。所以一换路、一重连，电量可能就空着——应用记着上一次的电量先顶上
  （`incott-battery-memory`）。预览的模拟层要跟着实测走：`asleep=1` 时 `0x89` 也回 0（之前它还回电量，把这条路盖住了）。
- **通知条整个去掉了，别再加回来。** 右下角那条小提示一共五种：设置开关成功、设置保存失败、设备断开、
  插线 / 拔线换连接、鼠标上按 DPI 键。除了「保存失败」，其余都是把屏幕上已经看得到的变化再念一遍，还挡住右下角。
  2026-11-26 用户先说点电量弹的那条「没有什么实际意义，且挡住了信息的显示」，又问点开机自启为什么弹、一共有几个，
  说「太小且不明显，没有显示的必要」。现在：成功的操作不提示；保存失败直接标在那一行设置下面（红字），控件退回原值
  （`app.js` 的 `showSettingError`）；窗口藏着时按 DPI 键仍然走 Windows 系统通知。
  **回显状态的小提示不加；错误信息放在它所属于的那一行里。**

录动效时踩的：

- **无头模式下 `--window-size` 含浏览器边框**，页面实际视口小一圈（1080×720 → 1050×625），
  按应用坐标写的裁剪框全都对不上。用 CDP 的 `Emulation.setDeviceMetricsOverride` 直接锁定视口。
  （`shot.mjs` 不受影响：`--screenshot` 模式下视口就是窗口尺寸。）
- **关掉 GPU 录会出假帧**：偶尔录到一帧「布局已经变了、动画还没生效」。默认用 GPU 合成
  （和应用的 WebView2 一致）；看到突兀的一帧，先在页面里用 rAF 采样计算样式确认，再下结论。
- **这台机器上的 `msedge.exe` 是个启动器**：把真正的浏览器进程起好之后自己就以 0 退出了。
  所以 `child.kill()`、`taskkill /T <启动器 pid>` 都什么也杀不到，得按启动时给的临时目录
  找到命令行里带着它的进程再关。残留的浏览器会一直占着调试端口，后面的录制全都连到它上面去。
- **PowerShell 5.1 按 GBK 读无 BOM 的 UTF-8 脚本**，文件头的中文注释被解坏，连带 `param(` 都没了。
  `.ps1` 一律存成带 BOM 的 UTF-8。
- **PowerShell 5.1 的 `ConvertFrom-Json` 把 JSON 数组当成一个对象输出**，
  `$frames.Count` 是 1、`$frames[0]` 是整个数组——要接一句 `| ForEach-Object { $_ }` 拆开。
- **`still` 只关 CSS 动画是不够的。** 换页、补位、显隐走的是 Web Animations API，不受
  `animation: none` 约束；而截图用的虚拟时间里动画帧不一定走得到，动画会一直挂在「待开始」，
  截出来停在半路（换页停在旧页）。所以 `still` 还让界面走「系统减少了动画」的分支
  （`mock.js` 里改写了 `matchMedia`）——顺带每张静态截图都在验证这条无障碍路径。
- **`msedge.exe` 是个启动器，`--screenshot` 模式下也是起好浏览器就返回。** 以前 `shot.mjs` 靠
  「进程退出 = 截完了」判断，Edge 更新之后不再成立：连续截多张时后一张在前一张写完之前就开始，
  结果几张内容相同、有的根本没被覆盖。现在等输出文件出现并且大小稳定下来才算完。
- **静态服务被一次断连带崩过**：请求处理器在 `catch` 里不判断连接还在不在就往回写，
  录帧用的浏览器被关掉时整个进程退出，之后的录制全都停在浏览器的错误页上。
  服务端加了判断；`motion.mjs` 也在导航失败或页面没就绪时立刻报错，不再等 40 秒后继续往下跑。
- **缩略图里的小圆点不能用来判断颜色。** 整窗的帧缩着看，读数屏的绿色指示灯像灰的、暗色文字像缺了一块，
  我差点当成切换时的闪烁去修。逐像素一量，几帧里都是同一个 `rgb(70,201,140)`；在页面里按帧采样 DOM 也没有中间态。
  判断颜色和有无，要量像素，或者在页面里采样。
- **`motion.mjs --all` 不要指定 `--out`。** 默认每个场景各用一个目录；指定了之后所有场景挤在一个目录里互相覆盖帧，
  有的场景被记成 0 帧。旧版录制器不把这当失败（退出码还是 0），现在 0 帧算失败。
- **录帧偶尔会一帧都没送到。** 全量跑的时候 `macro-slot` 出现过一次 0 帧，单独重跑四次都正常（18~20 帧），原因没查到。
  录制器现在遇到 0 帧会自动重录一次，第二次还是 0 才算失败——所以看到「一帧都没录到，重录一次」这行，
  说明碰上了偶发，不是回归；后面跟着 ✗ 才是真的有问题。
- **已安装的程序和构建目录里的程序哈希不一样。** Tauri 打包时先把程序放进安装包，再给构建目录里那份补上
  3 个字节的「安装包类型」标记，其余字节完全相同。核对「装上去的是不是验证过的那份」时，要么忽略这 3 个字节，
  要么直接找新代码里的特征字符串。
- **Git Bash 会把安装包的 `/S` 改写成 `S:/`。** 参数不对时 NSIS 不静默，安装向导停在第一页，不装也不退，
  命令一直挂着（2026-11-26 踩过；同样的写法之前是成功的，原因没查清）。写成 `MSYS_NO_PATHCONV=1 <安装包> /S`
  （或 `//S`），装完看一眼已安装 exe 的时间戳再继续。
